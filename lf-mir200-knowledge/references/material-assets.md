# 翎风补丁素材工作流

这份参考只处理**已完成首次接入确认**的项目。首次接入必须先锁定：

`服务端路径 → 客户端路径 → 补丁路径/加载优先级 → 对应版本说明书`

没有这四项，不要根据旧项目的资源编号写入数据库，也不要把上一套客户端的图片当成当前项目素材。

## 接入清单

先向用户确认并记录：

- 服务端目录：定位到包含 `Envir` 的那一层。
- 客户端目录：确认实际运行客户端使用的 `Data` 或等价资源目录。
- 补丁目录：可以有多个；记录加载顺序、同名资源覆盖规则和补丁密码清单。
- 说明书：记录版本标识、章节目录或用户提供的本地说明书根目录。脚本命令、字段语义和资源算法以这版说明书为准。

项目切换时重新确认全部清单。不要自动沿用上一项目的服务端、客户端、补丁、密码或说明书。

## 四类素材的职责

装备和道具的四类图片不是同一个资源：

| 用途 | 主要字段/资源 | 说明 |
| --- | --- | --- |
| 地图中人物穿戴外观 | 装备 `Shape` + `Hum*.wzl`（衣服）或 `Weapon*.wzl`（武器） | 受职业、性别、方向、动作帧和时装外显影响 |
| 装备栏内观 | `Looks` → `StateItem` | 是装备窗口中的大图，不要用人物外观单帧代替 |
| 背包小图 | `Looks` → `Items` | 物品格中的小图 |
| 地面掉落图 | `Looks` → `DnItems` | 地图上掉落物品的图 |

字段职责和扩展范围以当前项目对应版本的说明书为准。公开版说明书中可交叉参考：

- `knowledge_base/chapters/011-Stditem详解.md`
- `knowledge_base/chapters/816-物品和武器的扩展算法.md`
- `knowledge_base/chapters/015-特效计算.htm.md`
- `knowledge_base/chapters/361-修改装备内观和外观命令.md`

道具通常只需背包图与掉落图；用户要求的“钟的额外观”或 NPC 展示图是单独的展示素材，先确认当前版本的展示方式、资源表和脚本调用语法，不要把它当作装备 `Shape`。按“东皇钟”这类名称找图时，可以用名称语义筛选钟形候选，但最终要逐张对照用户的风格预期及客户端实际资源。

## Looks 的索引基

公开说明书的通用扩展算法是：

| `Looks` 范围 | 资源族 |
| --- | --- |
| `0-9999` | `Items`、`DnItems`、`StateItem` |
| `10000-19999` | `Items1`、`DnItems1`、`StateItem1` |
| `20000-29999` | `Items2`、`DnItems2`、`StateItem2` |
| `30000-39999` | `Items3`、`DnItems3`、`StateItem3` |
| `40000-49999` | `Items4`、`DnItems4`、`StateItem4` |
| `50000-59999` | `Items5`、`DnItems5`、`StateItem5` |
| `60000-65534` | `Items6`、`DnItems6`、`StateItem6` |

因此，数据库 `Looks=1396` 默认读取基础库的 `Items/DnItems/StateItem #1396`，不是 `Items1 #1396`。只有 `Looks=11396` 才按上述通用算法读取 `Items1 #1396`。这是素材预览最容易出现的错位。

项目的 `EffectImageList.txt`、资源登记表、启动器配置和实际补丁覆盖关系可以对通用算法做版本化修正；发现差异时，以已确认项目的运行配置和对应版本说明书为准，并在结果中说明例外。`EffectImageList.txt` 主要用于脚本展示资源映射，不应单凭它推断数据库 `Looks` 的资源来源。

## Shape 的预览

`Shape` 预览不能只取任意一张 WZL 图片：

1. 先根据说明书选择正确的 `Hum*.wzl` 或 `Weapon*.wzl` 文件。
2. 根据 `Shape` 计算资源文件和帧组。
3. 选择代表性的站立方向/动作帧；如果需要证明完整外观，返回一组方向或动画帧。
4. 单独标注这是“地图穿戴外观”。不要把 `StateItem` 大图误标为 `Shape` 外观。
5. 检查项目是否启用了时装外显、脚本 `SetItemShape` 或其他运行时改形；这些会让角色当前显示外观覆盖数据库原始 `Shape`。

`Light` 是衣服/武器的额外内观发光特效字段，不会替代 `Looks` 的内观、背包和掉落图。使用前必须按对应版本说明书确认特效资源和编号。

## 直接读取补丁

素材选择时按项目确认的补丁优先级直接读取资源，不要要求用户每次手动打开编辑器：

1. 扫描客户端基础资源和所有确认过的补丁。
2. 解析密码清单；密码只用于本地读取，不写入仓库、不回传。
3. 对 `Items`、`DnItems`、`StateItem`、`Hum`、`Weapon` 建立资源目录。
4. 为每个逻辑图片保存：资源文件、逻辑编号、宽高、透明边界、文件修改时间和缩略图。
5. 同名资源按运行时优先级保留最终版本，同时保留来源信息，便于解释“为什么读取的是这一张”。

素材读取器应支持 PAK、WIL/WZL 及当前项目说明书登记的其他格式。现有解析器不支持某个格式时，先说明缺口，不要把另一个格式的图片冒充结果。

仓库提供 `scripts/material_preview.js` 作为本地直读入口。它需要 Node.js 和用户机器上已安装的兼容 `pakEngineWorker.js`，由 `--worker` 显式指定；仓库不附带第三方解析器。它不会打开编辑器或启动游戏。例如：

```powershell
node "<技能目录>\scripts\material_preview.js" info --worker="<本机解析器>\pakEngineWorker.js" --file="<补丁>\Data\Items1.pak" --password-file="<服务端>\登录器\Pak.txt"
node "<技能目录>\scripts\material_preview.js" list --worker="<本机解析器>\pakEngineWorker.js" --file="<补丁>\Data\Items1.pak" --password-file="<服务端>\登录器\Pak.txt" --offset=0 --limit=100
node "<技能目录>\scripts\material_preview.js" export --worker="<本机解析器>\pakEngineWorker.js" --file="<客户端>\Data\Items.wzl" --index=1396 --out="<本地工作目录>\item.png"
```

密码表按 GB18030 读取；同名资源存在多个密码条目时优先精确路径。用户应先确认补丁的实际运行路径和加载优先级，再按逻辑编号选资源文件。解析器不兼容或缺失时先告知用户需要一个可用的本地解析器，不假装直读成功。

## 搜索与缓存

为了避免每次从头扫描：

- 已知物品名：先查当前服务端 `StdItems`，得到 `StdMode/Shape/Looks/Light`，再按资源索引取图。
- 按“钟、剑、红色、金色、铠甲”等描述找素材：只对已经建立的缩略图目录做候选筛选，再人工确认或输出候选组。
- 缓存资源目录、缩略图和感知哈希；文件大小、修改时间或哈希变化时增量重建。
- 变更客户端或补丁后，重新建立该项目的索引，不复用旧项目索引。
- 导入数据库后返回四张预览：地图外观、装备栏内观、背包图、掉落图；每张都标注资源库和逻辑编号。

语义识图只能生成候选，不能替代 `Shape/Looks` 和实际客户端资源的核对。候选搜索的结果要标明“相似素材”而非已确认的游戏显示效果。

## 用户明确要求入库时

仅在用户明确指定当前服务端并要求修改数据库时操作目标库；默认分析任务保持只读。先检查 `StdItems` 的实际结构、同名物品、最大 `Idx`、所属职业和该版说明书的字段含义；备份目标数据库，再在事务内新增或修改指定记录，回读全部关键字段并检查数据库完整性。保留备份位置，不运行 Mir200。

例如，用户要“男性战士衣服，双防 100-100，等级 1，10% 伤害吸收”：按对应版本说明书和当前项目同类装备确认 `StdMode`、`Ac/Ac2`、`Mac/Mac2`、`Need/NeedLevel`。公开版说明书的 [`016-天生元素字段说明.md`](../knowledge_base/chapters/016-天生元素字段说明.md) 将 `Element2=10` 定义为**物理伤害减少 10%**，不是所有伤害均减少 10%，也不是有限吸收池；若用户意思是别的吸收机制，应先核对需求和对应版本。确认 `Shape/Looks` 实际资源后才入库，并返回四类预览。

本节是操作流程，不授权改动任何用户数据库；同样的字段数字在另一版引擎中必须重新查证。

## 隐私与提交边界

补丁、客户端、服务端、密码表、缩略图和资源索引属于用户本地资料。它们只用于当前任务，不提交到公开仓库。技能仓库只保存通用工作流、版本确认规则和不含私有路径的工具说明。
